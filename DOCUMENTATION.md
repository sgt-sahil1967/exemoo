# Exemoo: Graphics, Assets, Audio and Algorithms

A complete reference for how everything in Exemoo is built: the landing page, the phone controller, the
camera and motion pipeline, and each of the seven games. Almost nothing ships as a binary asset. Textures,
models, sound effects and music are generated by code at load time, a few pieces of artwork are generated
offline with Gemini, and two character models are third-party CC0.

---

## 1. Overview

| Layer | Folder | What it does |
|---|---|---|
| Server | `server/` | Node HTTP (8080) + self-signed HTTPS (8443, needed for phone motion sensors) in `--lan` mode. `/signal` WebSocket for PIN rooms, `/api/info`, `/api/qr`, `/pad`, `/play/<id>/`, `/healthz`. |
| Shell | `public/` | Landing page, 3D farm background, cover art, game stage (iframes), camera assist, air cursor. |
| Phone pad | `public/js/pad*.js` | Controller UI, IMU streaming, sounds played on the phone. |
| SDK | `public/sdk/` | What games import to talk to the shell (`exemoo.js`) and compatibility adapters (`adapters.js`). |
| Games | `games-src/<id>/` (Vite + TypeScript) built into `games/<id>/`; `cricket`, `farm-dash`, `pad-test` are static. | Fruit Slice, Table Tennis, Pose Match, Tennis, Farm Dash, Golf, Cricket. |
| Tools | `scripts/` | `build-games.mjs`, `gen-cricket-assets.mjs` (Gemini SVG generator). |

Rendering is three.js everywhere (WebGL). Audio is Web Audio everywhere except Pose Match, which plays
pre-rendered WAV files that were themselves synthesised by script.

### Shared design language ("Moo Moo Farm")

- Ink colour `#1b1b3a`, chunky 4 to 6 px outlines, flat bright fills, hard offset drop shadows (`box-shadow: 0 5px 0 ink`).
- Fonts: Lilita One for titles, Baloo 2 for body.
- Palette: blue `#2f7cff`, yellow `#ffd21f`, red `#ff3b30`, green `#2fc65a`.
- Cricket, the landing page and the cover art all follow it. The other games keep their own looks.

## 2. Landing page and shared 3D scene

**`public/scene.js`** builds the farm background on every Exemoo page.

- `WebGLRenderer` with ACES filmic tone mapping (exposure 1.05), sRGB output, soft PCF shadows, pixel ratio capped at 2.
- Chunky shapes come from `RoundedBoxGeometry`, so every object has the soft toy-like edge.
- Checkerboard grass, fences, barn, hay, trees and 3D cows. The cows are grouped primitives (rounded body, head, spots, horns, legs) with a slow idle bob. The logo carries the same cow.
- Curb z-fighting (flicker of the red and white stripes) was fixed by sizing each block to the exact segment spacing so faces never overlap.

**`public/covers.js`** draws the cover art for each game card as inline SVG (400 x 220).

- Shared `defs(id, top, bottom)` give each cover a sky gradient, a checker grass `<pattern>`, a ground-shade gradient, a sun radial gradient, a drop-shadow `<filter>` (`feDropShadow`) and a glossy sheen gradient. The `id` prefix keeps gradient ids unique when several SVGs sit in one page.
- All strokes use the ink colour with round joins and caps (`S`, `S3` helpers) for the sticker look.
- Each game gets its own illustrated scene in that style (fruit, paddle and ball, pose figure, racket, runner, golf hole, cricket bat).

**`public/index.html` / `how.html`** are plain HTML and CSS: chunky buttons, a two-column game grid, footer placeholders, a QR popup on the right and a "how it works" page of short text with small visual cues. No emojis anywhere.

## 3. Pairing, networking and the phone controller

### Pairing
- The shell creates a six-digit PIN room over `/signal`. The QR encodes `https://<lan-ip>:8443/pad?...`; the PIN is also shown as text with the URL.
- The server regenerates its self-signed certificate when the machine's IP changes (`server/.cert/meta.json` records IP and hostname).
- `signaling.js` pairs one game screen and one controller per room, forwards `offer/answer/candidate`, and keeps a room alive for a grace period so a reloaded tab can resume it.
- **Transport**: the phone offers WebRTC with two data channels, `sensor` (unordered, no retransmits) and `control` (reliable JSON). If the channel is not open within 5 s, it falls back to relaying through the server (binary WebSocket frames plus `{type:'relay', payload}`).
- **Latency and clocks**: the screen pings; the phone's pong carries its own clock (`pt`). The lowest round-trip sample of the last 16 gives `phoneClockOffsetMs`, so a sensor packet's phone time maps onto screen time.

### SEN2 sensor packet (56 bytes, little-endian, ~60 Hz)
`magic 'SEN2' | seq | t(ms) | quaternion x y z w (f32) | linear accel x y z (f32) | gyro alpha beta gamma (f32, deg/s) | buttons bitmask (u32)`. The older 40-byte SEN1 packet still decodes with zero gyro and buttons.

### Phone layouts (`pad.js`)
The screen sends `{t:'layout'}`:
- `menu`: gyro "air mouse" pointer plus d-pad and A/B.
- `swing`: big hold-to-swing button, SEN2 streamed.
- `slice`: the whole screen is the blade.
- `remote`: GO / Pause / Back, no motion stream.
Calibration (recentre) is available on the menu layout. Start connects to the room immediately; the sensor permission prompt is raced against a 15 s timeout, and an on-screen diagnostics box shows errors.

### Phone sounds (`pad-sound.js`)
Synthesised on the phone with Web Audio so the bat crack comes from the hand. `bat` = a noise burst through an exponential decay plus a short triangle tone, brighter and louder for cleaner contact; `edge` = thin tick; `four` / `six` = two or three rising notes; `wicket` = falling notes. `unlockSound()` runs from the Start tap (browsers need a gesture; a silent oscillator blip finishes the iOS unlock).

## 4. Camera assist and sensor fusion

Phone IMUs know orientation well but drift in heading and cannot know absolute position. The webcam knows where the wrist is but is noisy and low rate. Exemoo fuses them.

### `public/js/camera.js`
- MediaPipe Pose Landmarker (lite model, about 30 fps) runs in the shell.
- Emits `pose` with the wrist, elbow and shoulder in mirrored image coordinates (x grows to the player's right), a body `scale` (shoulder width), visibility, and a capture time `at` already corrected for camera latency on the shared epoch clock. Raw 2D landmarks (`img`) and 3D world landmarks (`world`, metres) are included for games that track arms themselves.
- `HeadingFusion` drift-corrects the packet heading using the camera's arm direction, so a phone whose yaw wanders stays aligned with the player.
- The shell attaches `cam` to each forwarded packet. Pose Match and Farm Dash use their own camera (`OWN_CAMERA`).

### Filtering
Both the pointer paths (Fruit Slice) and Pose Match landmarks use the **One-Euro filter** (Casiez et al. 2012): an adaptive low-pass whose cutoff rises with speed (`alpha = 1/(1+tau/dt)`, `tau = 1/(2*pi*cutoff)`), so it is steady at rest and responsive in motion.

### Per-game use
| Game | Phone IMU | Camera |
|---|---|---|
| Tennis | swing speed, face angle, timing | absolute racket position |
| Table Tennis | swing intensity and angle | paddle position, 5 lanes (left, mid-left, mid, mid-right, right); the ball is only hit when the bat is in its lane |
| Golf | impact timing, face twist, path | backswing height and downswing speed (`CamSwing`), fused with the IMU swing |
| Fruit Slice | blade pitch and yaw | pointer position |
| Cricket | bat timing and shot sounds | hands set direction, lift and power |
| Pose Match / Farm Dash | remote only | full-body pose |

## 5. Games

### 5.1 Fruit Slice (`games-src/fruit-slice`)
**Graphics**
- *Geometry* (`assets/geometry.ts`): fruit bodies are closed parametric surfaces built by `buildSurface(segU, segV, fn)`, a (u, v) grid with single pole vertices and a duplicated UV seam column. Normals are smoothed across the seam. "Weld ids" are stored in `geometry.userData.weld` so cuts can cross UV seams. Stems, leaves, crowns and seeds are merged attachment meshes cached per kind and flagged shared, so spawning a fruit is cheap.
- *Textures* (`assets/textures.ts`): skins are painted onto canvases (u around, v bottom to top) using a seeded `mulberry32` PRNG. Flesh faces are painted in Cartesian space and resampled to polar layout (u = angle, v = radius) so the rind and pith rings follow the true cut outline.
- *Slicing* (`assets/slicer.ts`): the cutting plane `n . p = 0` splits every triangle crossing it, interpolating position, normal and uv. Cut points are shared per topological edge (using weld ids), chained into closed loops and capped. Star-shaped loops get concentric rings with polar UVs; non-star loops (a banana lengthwise) are ear-clipped. The two halves become separate meshes with their own physics.
- *Effects* (`fx/`): bloom (`PostFX`, UnrealBloomPass, only on high quality), pooled additive spark particles in an `InstancedMesh`, juice drops and puffs, juice stains drawn into a canvas decal on the table (max 500, redrawn at 15 Hz or less), screen-space splats with drips and an ice frost frame, trauma-based camera shake with spring kicks and idle sway, and a GPU blade-trail ribbon (custom shader, 64 samples, 0.16 s life).
- *Environment*: procedural wooden table (12 planks, colour plus bump canvases) built with rounded boxes.

**Gameplay logic** (`game/Spawner.ts`): a wave director emits launch requests (kind, x, apex, drift target, delay, optional side launch for frenzy streams) with density and danger ramping up over time.

**Input**: `MotionPointer` converts phone yaw and pitch to a screen pointer with a One-Euro filter, extrapolation of at most 24 ms past the last packet, and recenter on the calibrate button. Camera assist supplies the pointer; the blade colour trail follows it. A mouse path is always available.

**Audio** (`audio/`): fully procedural, theme "warm wooden dojo".
- `SoundEngine` graph: voices to `sfxBus`, tracks to a ducking stage to `musicBus`, both into a mix, then muffle low-pass, glue compressor, master gain, limiter, soft clipper, analyser. Reverb uses a generated impulse response.
- Every SFX is rendered once per variation into an `AudioBuffer` with an `OfflineAudioContext` at construction (works before any gesture), so playback is just a buffer source.
- Instruments: Karplus-Strong plucked strings (koto, bass, harp), a taiko and wood-block drum kit, shaker noise, a saw pad and a breathy shakuhachi voice.
- Music (`music.ts`): a lookahead-scheduled sequencer with three styles (`menu`, `game`, `frenzy`) in D major pentatonic, tempo and pitch scaled by a time factor so slow-motion also slows the music.

### 5.2 Table Tennis (`games-src/table-tennis`, "Spinshot")
**Graphics**
- `scene/stage.ts` owns the renderer (ACES filmic, PCF shadows), a fixed light rig (constant light count so switching themes never recompiles shaders), table, avatars, ball, FX, scoreboard and camera.
- `scene/arena.ts`: two environment themes, a bright community hall (`club`) and an evening `arena`, mesh-only; the stage retunes lights per theme.
- `scene/textures.ts`: every texture is a canvas drawn in code.
- `scene/avatar.ts`: low-poly characters from capsules, spheres and rounded limbs with **two-bone IK** for the paddle arm (hand to grip) and legs (planted feet that step).

**Physics** (`physics/core.ts`, `solver.ts`)
- Fixed sub-step of 1/720 s, so 60/72/90/120/144/240 Hz frames divide evenly.
- Midpoint (RK2) integration of gravity, quadratic drag and **Magnus lift**, with exponential spin decay.
- Near the table, net, posts and floor the step splits into micro-steps of 4 mm or less. Sphere-vs-box contacts are resolved with time back-tracking (rewind to contact, apply impulse, re-advance), so the 3 mm net can never be tunnelled.
- Contact impulse: normal restitution plus Coulomb friction on the contact-point slip velocity, limited to the roll-without-slip impulse, with angular momentum transfer for a thin spherical shell (I = 2/3 m r^2). Topspin kicks the ball forward and low, backspin the reverse.
- The live ball, `predictPath`, the shot solver and the intercept finder all share this core, so predictions match the live ball exactly.
- `solver.ts` finds shot parameters for a requested landing and finds intercept points inside the comfortable strike zone (ball height 0.02 to 0.55 m above the table).

**AI** (`game/ai.ts`): predicts the path, finds an intercept and plays a shot with difficulty-dependent error.

**Input**: swing detection from IMU, plus the 5-lane camera check described in section 4.

**Audio**: `audio/sfx.ts` synthesises hits, bounces, net and crowd with Web Audio (graph: voices to sfxGain, music to musicGain, both to master, compressor, destination); `audio/music.ts` is generative: a chill lo-fi loop for menus and a brighter driving loop for matches, with swing (off-beat delay), chord progressions, a scale for melody and crossfading tracks. Voices disconnect themselves when finished.

### 5.3 Pose Match (`games-src/pose-match`, "Pose Portal")
**Graphics**
- `scene.ts`: three.js with `RoomEnvironment` image-based lighting, EffectComposer with bloom, neon colour lights (`#ff3d8b #7dfcff #ffd02a #9b4dff`). Walls spawn at z = -46 and travel toward a fixed camera. The strong glowing lights in front of the character were reduced.
- `figure.ts`: a pearly clear-coat `MeshPhysicalMaterial` body (sheen, emissive) that tints green on a good match and red on a bad one.
- `skeleton.ts`: a fixed-size skeleton (spine 0.52, upper arm 0.29, forearm 0.27, thigh 0.45 ...). Pose sources only supply **bone directions**, never lengths, so every player fits the same wall openings.
- `poses.ts`: wall definitions (armsUp, wide, tpose, duck, jump, star, squat, flamingo, disco and more), each an axis-aligned opening in the wall plane plus a target skeleton solved by `solveSkeleton`.
- `walls.ts`: a 4.6 x 2.7 m wall drawn on a 1024 px canvas; holes are cut around each target bone with generous radii (0.19 m, torso 0.16 m, with extra for head and torso) and the figure's sampled body points are tested against the hole.
- `fx.ts`: one instanced mesh of up to 600 confetti, foam and droplet particles.

**Tracking** (`tracker.ts`, `pose-detector.ts`, `pose-worker.ts`)
- MediaPipe Pose Landmarker in a Web Worker (WASM files and the `lite` and `full` `.task` models ship in `public/`).
- Landmarks pass a One-Euro filter bank, then bone directions are derived.
- Calibration averages samples over a window (not a single frame) to avoid jitter resets, starts on the lite model and has watchdogs against freezes after the model switch. Leg spread is measured from the hip and ankle geometry.

**Audio**: sound effects are WAV files in `public/sounds/` rendered offline by `scripts/gen-sounds.mjs` from hand-authored synth recipes (`scripts/sound-recipes.mjs`, saved as JSON in `sounds/recipes/`). A recipe has layers of waves (`sine square saw triangle noise`), exponential frequency sweeps, note lists, ADSR envelope, filters, vibrato, FM (ratio, index, decay), plus optional echo and reverb; `loop: true` folds tails back to the start for seamless loops (the music). Files: click, go, tick, pass, splat, whoosh, warn, lifelost, gameover, newbest, music. Announcer lines ("Three!", "Go!", "Perfect!", "Arms up!") use the browser's speech synthesis.

### 5.4 Tennis (`games-src/tennis`)
**Graphics**
- `scene/court.ts`: playing surface, lines, net and posts with colours swappable per theme; textures from canvases and a procedural grain texture.
- `scene/stadium.ts`: two themes (`midnight`, `riviera`) with their own fog, bloom strength/radius/threshold, ad boards (`adCanvas`), glow sprites and a scoreboard.
- `scene/crowd.ts`: the audience is billboard sprites seated on seat positions facing the court, textured from a generated crowd atlas with a 20-colour shirt palette.
- `players/athlete.ts`: stylised athletes with outfits (shirt, shorts, skin, hair, shoes, band, racket) and procedural forehand, backhand and serve animations; `racket.ts` builds the racket.
- **Artwork from Gemini**: `scripts/gen-svg.mjs` asks Gemini for SVGs (ad boards, crowd pieces) and writes them to `assets/svg/`. `assets.ts` loads them with `import.meta.glob`; any missing file falls back to a procedural drawing, so the game always renders.

**Physics** (`physics/ball.ts`): fixed step 1/240 s, gravity 9.81, quadratic drag (k = 0.0195), Magnus (k = 0.11), restitution 0.76, net collision using `netHeightAt` (sagging net), bounce and net events.

**AI** (`game/ai.ts`): from a predicted ball path it picks a contact (time, position, first bounce, stroke), moves there and aims with Gaussian error scaled by difficulty.

**Audio** (`audio.ts`): all synthesised. Ball hits, bounces and net are noise plus oscillators; the crowd is a looped filtered-noise bed with a generated applause buffer that swells on points.

### 5.5 Golf (`games-src/golf`)
**Course generation** (`course/`)
- `noise.ts`: seeded `mulberry32`, 2D value noise, smoothstep, and "blobs" (wobbly rotated ellipses with an approximate signed distance in metres) for greens, bunkers, water and islands. No `Math.random`, so every hole is deterministic.
- `hole.ts` turns an authored `HoleSpec` (centreline, fairway profile, green, bunkers, water, tree rules, elevation) into a `Hole`. Terrain height = inverse-distance-weighted elevation profile plus value-noise hills, then features are stamped on: a tee platform, a green plane (1 to 3 percent slope, optional tier), bunker bowls with lips, water basins with banks. Heights are precomputed on a 1 m grid with bilinear lookup; within about 16 m of the green the analytic function is used so putting is perfectly smooth. Surface priority: water > sand > green > fringe > tee > fairway > rough > deep rough > out of bounds.

**Graphics** (`scene/`)
- `terrain.ts`: one height-field mesh plus a rising skirt, coloured by a baked "splat" canvas texture (surface colours, mowing stripes, bunker lips, soft edges).
- `trees.ts`: instanced stylised trees (round, stacked-cone pines, palms), bushes, rocks, flowers.
- `sky.ts`: sky dome shader, distant hills, drifting low-poly clouds and occasional birds.
- `water.ts`: custom shader with ripples, fresnel, sun glint and shore foam.
- `golfer.ts`: a primitive-built golfer posed procedurally each frame: club and hands move in an inclined swing plane, shoulders and hips turn with the swing, arms and legs solved with two-bone IK.
- `greenGrid.ts`: Wii-style putting grid draped on the green, tinted by height, with dots flowing downhill (additive-blended shader points).
- `fx.ts`: instanced chunky bits (turf, sand, droplets, leaves, confetti), puffs and rings.
- Performance: 60 fps cap, MSAA only when the device pixel ratio is below 1.5, shadow map `autoUpdate = false` with `needsUpdate` every other frame. Quality is unchanged.

**Physics** (`physics/ball.ts`): sub-steps of 2 ms or less. Phases `flight`, `rolling`, then `rest | holed | water | ob`. Launch speed for a target carry is found by inverting a per-club carry-vs-speed table computed lazily on flat ground. Target carry = club carry x power scale (linear to 1, up to +8 percent overswing at 1.15) x lie multiplier x strike quality (below 0.4 is a topped shot). A `forceStop()` watchdog ends a ball that creeps near the flag forever.

**Swing input**
- `phoneSwing.ts` processes each sensor packet: drops stale packets, derives angular velocity (gyro cross-checked against quaternion differencing), computes swing-plane quantities and runs the `SwingDetector` state machine. Auto-calibrates the address pose when the phone is still and pointing down for 0.6 s.
- `camSwing.ts` (camera) tracks hands as address, back, down, follow. Units are shoulder widths so distance from the camera does not matter. It emits an impact with backswing `rise`, peak hand `speed` and sideways `path` (out-to-in slice or in-to-out hook).
- Fusion: the IMU supplies timing, face twist and path; the camera supplies absolute backswing and speed. Whichever event arrives first is held and fused within a short window.

**Audio** (`audio/`): `engine.ts` is the shared Web Audio core (master, music and sfx gains, noise buffer, `mtof`); `sfx.ts` has synthesised one-shots (club strikes, cup, splash, UI); `music.ts` is a lookahead scheduler on audio time with crossfades between `menu`, `course` and `results` tracks, using FM electric-piano and marimba voices; `ambience.ts` is looped band-passed breeze noise with random birdsong. The swing whoosh was removed.

### 5.6 Farm Dash (`games/farm-dash`)
Static ES modules, three.js loaded from a CDN, nothing prebuilt.
- `assets.js`: every texture, material and mesh is generated at runtime (graffiti tags, train cars, ramps).
- `player.js`: an original runner character ("Juno") from rounded primitives with **toon shading** (`MeshToonMaterial` with a 4-step `DataTexture` gradient map giving hard light bands) and ink outlines, animated procedurally.
- `world.js`: three lanes at x = -2.5, 0, 2.5; track segments spawn at z = -150 and scroll toward +z while the player stays at z = 0; collision queries with step-up height 0.8; despawn at z = 25.
- `fx.js`: pooled dust, sparkles, shockwaves, speed lines and power-up auras from canvas textures.
- `ambient.js`: birds, clouds, animated billboards, signals, steam vents and flickering lamps with no real lights (avoids shader recompiles).
- `audio.js`: procedural Web Audio at 126 BPM, A-minor progression (Am, F, C, G) with an arpeggio pattern and bass, scheduled with a 100 ms lookahead on a 25 ms timer.
- Control: the camera's pose (`pose-camera.js`) or phone tilt for lane changes.

### 5.7 Cricket (`games/cricket`)
Endless mode: play until out. A new game, written for Exemoo.

**Graphics**
- `world.js`: renderer and lighting, turf and pitch, stadium with painted crowd, foliage and the farm beyond. The stadium has no grass on the stands. The crowd is painted into row textures rather than modelled per fan, which keeps the frame rate high while keeping detail. `BOUNDARY = 64`, ground centre at `FIELD_Z = -10`. A seeded PRNG (`mulberry`) makes the scene identical every run. Geometry is merged (`mergeGeometries`, with a wrapper that converts to non-indexed so attributes match) to cut draw calls.
- `svg.js`: all stadium artwork is SVG rasterised at high resolution into `CanvasTexture`s by `svgTexture(svg, w, h, {repeat, anisotropy, bg})` (draw the SVG into a canvas via an `Image` and a `data:` URL, flag `needsUpdate` on load). It makes ad boards, crowd rows, stand fascias, roof panels, the sight screen, the scoreboard, shirts, faces, pads, gloves and helmets, in the Exemoo ink-outline style.
- **Gemini artwork**: `scripts/gen-cricket-assets.mjs` calls Gemini (`gemini-3.8-flash`) for the cricket ball leather (equirectangular), bat sticker, two team crests, four stand fascias (2048 x 128, tiling) and six sponsor boards. Each response is validated: a single `<svg>` only, no scripts, event handlers, `foreignObject` or external references, size limit, viewBox and size fixed up, up to three retries. Files land in `assets/gen/` with a `manifest.json`; `genassets.js` loads them at runtime and any missing file keeps the built-in look.
- `rig.js`: a `Humanoid` with an invisible jointed "driver" skeleton (17 joints), forward-kinematics poses with blending, a run cycle and **two-bone arm IK**, so batters' hands stay on the bat handle through every shot. It draws as a toy figure until a rigged model loads, then the model's bones follow the driver every frame, recoloured in the team kit. Helmets, caps, pads and gloves are attached to the driver joints. Textures are cached by kit so nine fielders share one set.
- Player models (`models/`): `player-men.glb` (Man in Long Sleeves) and `player-women.glb` (Woman Casual) by Quaternius, CC0, from Poly Pizza (see `models/CREDITS.md`).
- `trail.js`: ball trail as a tapering camera-facing ribbon through the last 0.35 s, 40 points, per-vertex colour and alpha (white for deliveries, gold for PERFECT, orange for EDGED).
- `timingbar.js` and `handcam.js`: DOM and CSS overlays. The timing bar's zones are generated from the physics grades so the display always matches the rules. The hand overlay draws the mirrored webcam with tracked arms, hand trail and swing arrow.
- Camera sits behind the striker's stumps, like broadcast cricket.

**Ball physics and shot model** (`physics.js`, no three.js, so Node tests use the same maths)
- Gravity 9.81, ball radius 0.036 m, bounces with restitution and friction.
- A shot is the camera intent `{direction, lift, power}` plus the timing error (seconds, negative = early). Timing grades by absolute error: PERFECT 45 ms, GOOD 95 ms, MISTIMED 180 ms, EDGED 250 ms, beyond that a miss. Contact quality falls off sharply with error, and both exit speed and launch angle depend on it: early shots are dragged to the leg side and lose distance, late ones steer off side, a badly mistimed lofted shot goes up rather than out (a catch). Edges fly behind the wicket.

**Camera batting** (`batcam.js`)
- `ArmTracker` follows shoulder, elbow and wrist on both arms, learns limb lengths, and coasts a blurred joint from its last angle and spin for up to 0.2 s. Joints count as seen above MediaPipe visibility 0.35.
- `SwingDetector` watches the midpoint of the wrists in body widths per second, finds where the hands left rest, and reads the stroke: sideways versus forward sets direction (mostly-sideways strokes are squared up), upward share sets lift (lofted when lift is at least 0.35), distance and speed set power. A quick backlift may start a swing; when the hands turn into the real stroke the swing restarts from that point. Impossible frame-to-frame jumps are discarded as tracking glitches. `contactAt` is the swing onset plus a lead that shrinks for faster swings. See `HOW_TO_BAT.md` for the player-facing rules.
- `imu.js` extracts phone motion features (rotation by quaternion, pointing heading, vertical rise) for the training log.

**Fielding AI** (`fielding.js`): at contact the ball path is predicted; for each fielder and the keeper the planner finds the earliest reachable point on that path considering reaction time (0.3 s, keeper 0.12 s), sprint speed 7.4 m/s with acceleration, and reach (ground 1.0 m, catch 1.25 m, dive 2.3 m, catchable heights 0.15 to 2.5 m). The first to arrive takes it as a catch, a stop or a dive; catches can be dropped and hard stops fumbled; a ball that beats everyone is a four or six; runs are what the batters can complete before the throw (30 m/s, 0.25 s release) reaches the keeper.

**Audio** (`main.js`): Web Audio `tone(freq, dur, type, vol)` oscillator blips (a lower tone for a wicket, a bright tone for a perfect hit, a high tick for an edge, a short bounce tick) plus the pad-side bat, boundary and wicket sounds.

## 6. SDK and ported games

`public/sdk/exemoo.js` (`connectExemoo`) gives each game: `nav` (menu navigation), `airCursor`, `setCamera`, `pressKey`, and the stream of decoded sensor packets with camera data. `adapters.js` provides `SpinshotLink` (Table Tennis and Golf) and `SliceLink` (Fruit Slice, which needs the legacy quaternion Euler order, rebuilt by `legacyQuat`) so the original input code continues to work unchanged inside the shell. Original game folders stay untouched; `games-src/` copies are built by `scripts/build-games.mjs` (runs Vite per game) into `games/`.

## 8. Algorithms index

One-Euro filter; Karplus-Strong pluck synthesis; FM synthesis; lookahead audio scheduling; seeded PRNG (mulberry32); value noise and fBm; inverse-distance-weighted terrain; signed-distance blobs; plane-mesh slicing with loop chaining and polar capping; RK2 ball integration with drag and Magnus; time-back-tracked sphere-box collision; shot solving and intercept search; two-bone IK; forward kinematics pose blending; toon shading ramps; instanced rendering; UnrealBloom post-processing; WebRTC data channels with relay fallback; round-trip clock synchronisation; complementary heading fusion; hand-swing state machines (golf and cricket); reachability planning for fielders.
